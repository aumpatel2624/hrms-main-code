Rules the code must uphold. Each one is written so you can tell whether an implementation satisfies
it, and says **where it is enforced** — because a rule enforced only in the browser is not enforced.

Format: one rule per row, stable id, so a commit or a test can cite it.

| ID | Rule | Enforced in |
|---|---|---|
| CALC-1 | Working hours calculations support all four combinations of `workingHoursCalculationBasedOn` ("First Check-in and Last Check-out" vs. "Every Valid Check-in and Check-out Pair") and check-in log handling (strict IN/OUT pairs or alternating punches). Resulting total hours are evaluated against `workingHoursThresholdForHalfDay` and `workingHoursThresholdForAbsent` on the linked `ShiftType` to categorize attendance status. | `apps/server/utils/workingHours.js` (`calculateWorkingHours`), tested in `workingHours.test.js` |
| CALC-2 | `SalaryStructureAssignment.annualGrossEarning`/`.ctc` (ADR-026): `grossPerPeriod` = sum of `earnings` rows' evaluated amount, excluding any row flagged `statisticalComponent` or `doNotIncludeInTotal`; `employerContributionsTotal` = sum of `employerContributions` rows excluding `statisticalComponent`. `PERIODS_PER_YEAR = { Monthly: 12, Fortnightly: 26, Bimonthly: 24, Weekly: 52, Daily: 365 }`. `annualGrossEarning = grossPerPeriod × periods`; `ctc = (grossPerPeriod + employerContributionsTotal) × periods`. A row's `formula`/`condition` is evaluated with `base`/`variable` from the assignment plus every earlier-evaluated row's abbreviation in context (earnings → deductions → employer contributions order); a condition-false row contributes 0 and injects no context entry at all. `SalaryStructure.totalEarning`/`.totalDeduction`/`.netPay` reuse the same row-evaluation machinery with `base`/`variable` defaulted to 0 — `totalDeduction` is NOT exclusion-filtered the way `totalEarning`/`grossPerPeriod` are (nothing in the real spec filters a deduction row out of any total). | `apps/server/utils/payrollCtc.js` (`computeStructureTotals`, `computeCtcAndGross`), tested in `payrollCtc.test.js` |
| CALC-3 | A `SalaryDetail` row's denormalized flags (`abbreviation`, `statisticalComponent`, `isTaxApplicable`, `variableBasedOnTaxableSalary`, `dependsOnPaymentDays`, `exemptedFromIncomeTax`, `doNotIncludeInTotal`, `accrualComponent`) are copied from the referenced `SalaryComponent` ONCE, at the moment that row is first added to a `SalaryStructure` — never re-copied on a later save, even if the master component's own flags change afterward. Row identity across an update is the subdocument's own Mongoose `_id`; a row with no matching `_id` is treated as brand-new and gets a fresh copy. | `payroll.controller.js`'s `buildRows` |
